# Skill: order_builder

## Purpose

Converts a messy natural-language order request into a structured, validated
order ready for barista preparation. Identifies missing fields, flags inventory
issues, and generates a follow-up question when clarification is needed.

## When to Use This Skill

Use this skill when:
- A customer places an order in natural language (in-person, chat, or voice).
- A recommendation has been accepted and needs to be formalized.
- An order is being re-entered after a service recovery event.

## Inputs

| Field | Type | Required | Notes |
|---|---|---|---|
| raw_order | string | Yes | The customer's full order as spoken/typed |
| store_id | string | Recommended | Needed for inventory check |
| date | string | Recommended | YYYY-MM-DD |

## Data and Tools Used

1. **`build_and_validate_order(raw_order, store_id, date)`** — primary parsing tool.
   Returns: structured_order, missing_fields, inventory_warnings, prep_notes, follow_up_question.
2. **`get_menu_item_info(item_name)`** — enriches the resolved item with nutrition and dietary flags.
3. **`check_inventory_status(store_id, date, ingredients)`** — verifies ingredient availability.
4. **`item_name_mapping.csv`** — used by the tool to resolve item names (do not read directly).

Do NOT call these tools by reading CSVs manually.

## RAG Documents Used

- `order_confirmation_standard.md` — confirmation sequence and required fields.
- `customization_policy.md` — what customizations are accepted and how to document them.
- `dietary_allergen_guidance.md` — response protocol for allergy-flagged orders.
- `drink_quality_consistency_sop.md` — prep notes must include "individually" statement.

## Step-by-Step Instructions

1. Call `build_and_validate_order(raw_order, store_id, date)`.
2. Check `missing_fields`:
   - If `size` is missing: ask `follow_up_question` (already generated by the tool).
   - If `temperature` is missing: ask `follow_up_question`.
   - If `item_name` is missing: show `candidates` and ask which the customer meant.
   - **Do NOT guess missing required fields.** Always ask the customer.
3. Check `inventory_warnings`:
   - For each warning, inform the barista (not the customer yet).
   - Propose a substitution per `inventory_substitution_sop.md`.
4. Check `human_review_required`:
   - If True (allergy/medical language detected): escalate to barista/manager before proceeding.
   - Do NOT finalize an allergy-flagged order without human confirmation.
5. Review `prep_notes` — ensure "Prepare individually for quality consistency." is present.
6. If all fields are present and no warnings: proceed to `order_summary` skill.

## Human Review Requirements

- If `human_review_required = True`: stop and escalate. Do not finalize.
- If `missing_fields` is not empty: do not proceed to order_summary until resolved.
- If `inventory_warnings` indicates unavailable ingredient: confirm substitution before proceeding.

## Edge Cases and Failure Cases

| Scenario | Action |
|---|---|
| Customer gives size in non-standard terms ("medium") | Tool normalizes — verify normalized value is correct |
| Multiple items ordered | Process each item as a separate order |
| Ambiguous item name | Present candidates; ask customer to choose |
| Allergy detected | Flag human_review_required; escalate |
| Substitution needed | Confirm with customer before finalizing |

## Handoff to Next Step

Pass `structured_order` and `prep_notes` to the `order_summary` skill.
Include any substitution notes in the `customizations` field.
