# Human Review and Control Plan

All review actions (`approve`, `edit`, `reject_rerun`, `escalate`) are wired to real outcomes in the orchestrator's `review_actions` dict. The `review_queue` lists each step flagged for human attention with a risk level and reason. The planned Review screen (M04 UI) will surface the AI-generated answer, the source docs/tool outputs used, and action buttons.

| Process step | What the AI does | What the human does | Human approval required? | What could go wrong? | What should happen if there is a problem? |
|---|---|---|---|---|---|
| **1. Inventory monitoring** | Reads `store_inventory.csv` for the requested date; classifies each ingredient as healthy/low_stock/overstock/unavailable; counts alerts; applies latest-prior snapshot if no exact-date row exists | Reviews the alert list; checks whether any critical-low item is a high-volume modifier (e.g., oat milk, vanilla syrup) | No — informational only, but items with `unavailable` status automatically queue for review | Snapshot date is stale (last inventory update was days ago); a "Healthy" status may not reflect today's actual stock | Surface the snapshot date in evidence; if snapshot age > 2 days, add a `stale_data` warning and require human confirmation before acting on the briefing |
| **2. Staffing gap calculation** | Counts unique scheduled employees whose shift covers the requested hour; compares to a baseline required headcount; classifies as Understaffed / Balanced / Overstaffed | Reviews the staffing status before the rush; can manually adjust by calling in additional staff or releasing early shift | No — advisory; manager uses output to decide | Shift data for the date is missing or the hour falls in a gap between two shifts; "Balanced" at hour 8 may become "Understaffed" at hour 9 | If no staff row matches the requested hour, return `status: no_data` and flag for human review; include next-available shift start time in evidence |
| **3. Rush-period detection** | Aggregates historical order counts for the store/hour from `order_history.csv`; cross-checks `daily_sales_forecast.csv`; classifies demand as low/moderate/high/very high; sets a risk level | Reviews demand classification and barista guidance; decides whether to open an extra register or pull a barista from food prep | No — advisory | Order history is sparse (new store or unusual date); demand may be misclassified as "Low" when forecast says otherwise | If fewer than 3 historical data points exist for the store/hour, surface a `low_sample_size` warning; use forecast as primary signal in that case |
| **4. Barista drink recommendation** *(explicit review point)* | Calls `search_menu_by_preferences()` to score all menu items against user preferences; checks inventory availability for top candidates; retrieves relevant RAG docs (allergen guidance, recommendation guidelines); returns ranked candidates with inventory status | Reviews recommended items and evidence; checks that allergy flags are visible; **must approve before the recommendation is delivered to the customer** | **Yes** — `review_required = True` always set on recommendation step | Top candidate is out of stock; allergen not flagged because ingredient is "not_tracked" in inventory; recommendation ignores an active promotion that would reduce cost | If top item is unavailable, show next in-stock alternative; allergen detection uses menu CSV directly (not just inventory), so not-tracked items are still checked; promotions are surfaced in evidence for manual verification |
| **5. Order building and validation** *(explicit review point)* | Parses natural-language order text with regex (size/temperature/milk/syrups/toppings/qty); resolves item name via 4-step mapping + menu search fallback; checks inventory for all parsed ingredients; detects allergen phrases in the order text | Reviews the parsed order fields before submission; corrects misidentified item, wrong size, or missing modifier; **approves or edits before the order is finalized** | **Yes** — if `item_resolved = False`, `missing_fields` is non-empty, or any ingredient is `unavailable` | "Iced venti oat latte" parsed correctly but "venti soy dirty chai" mis-resolves to Chai Tea Latte (misses "dirty" espresso shot); size token stripped too aggressively leaves an unresolvable name | Any unresolved field populates `missing_fields`; orchestrator pauses on `review_required = True`; human is shown the raw order text, the parsed fields, and the best match found |
| **6. Order summary and confirmation** | Generates a customer-facing confirmation and a barista prep note from the validated order fields; retrieves `order_confirmation_standard.md` and `drink_quality_consistency_sop.md` via RAG; checks that all required fields are present | Reviews the confirmation message for clarity and accuracy before displaying to the customer; checks that the prep note matches what was ordered | No — if order was approved in step 5, summary is auto-generated; manager can override | Summary states wrong milk type because the resolved item name default differs from the modifier parsed in step 5; prep note omits a requested syrup that was added as a custom note | Order builder passes a `customizations` field with all non-standard additions; summary must render each one; if the RAG doc score is 0 (no match for confirmation standard), add a `weak_evidence` warning and require a final human sign-off |
| **7. Evidence quality gate** | `build_evidence_package()` scores all evidence across the full run (RAG docs, tool outputs, inventory data) on a 0–1 scale; if score < 0.4, sets `review_required = True` on the workflow | Reviews the evidence quality badge and decides whether to approve the run or reject and re-run | **Yes** — if quality score < 0.4 | A valid-looking workflow run has no RAG docs retrieved (all scores = 0) and only one tool output; the AI's recommendation is unsupported | The review screen shows the quality score and the specific gap (e.g., "no knowledge base documents matched allergen query"); human can `reject_rerun` to trigger a re-run with a broader query, or `escalate` to a senior manager |
